# EMA + 权重0.1：缩短迭代轮次

2026-10-16，`tmp-gpu-ema` 分支。固定 `post_retract_mode=ema_lpa`、`wire_weight=0.1`，仅扫描 `max_iterations`。本轮没有修改算法或代码默认值。

## 建议

- **50轮是速度与线长的折中选择**：2.113→1.490秒，快29.48%；增加线长2453.232→2464.489µm，多11.257µm（0.459%）。≥5nm仍36条，小违例44→48条，最大残差17→19nm。
- **75轮更保守**：快15.98%，增加线长仅多3.481µm（0.142%），最大残差仍17nm；小违例48条。
- **30/26轮偏向速度**：约1.272/1.228秒，但增加线长分别多21.229/24.684µm，最大残差升到22/23nm。≥5nm数量仍36不表示残差质量完全相同。
- 已测25轮及更低的1/5/10/15轮，≥5nm数量均增加；本次最少保持36条的已测预算是26轮。没有声称所有未测轮数都必然更差。

## 为什么时间没有按轮次等比缩短

100轮的迭代耗时中位数为1161.543ms，50轮为533.494ms；后处理仍分别需要349.632/370.937ms，此外还要建图、准备数据和独立末态检查。
26轮的迭代仅276.424ms，后处理仍365.574ms；继续削轮数时，固定开销占比变大。
25轮比26轮没有更快的实测中位数，且违例数量上升，故不推荐把预算继续盲目减小。

## 调度和质量口径

- 保持原有0.25W步长、35nm跳跃、adaptive学习率1.5→0.5、零次步长减半，整数后处理24/8/8，联合搜索关闭。
- 学习率的余弦上限会随预算自动压缩，所以低预算轨迹不是100轮轨迹的简单截断。反馈窗口仍是8轮。
- 约束权重保持原代码：`lambda=10*2^min(3,floor((iteration-1)/25))`。1–25轮为10，26–50轮为20，51–75轮为40，76轮起为80。
  因此26→25轮还会失去第一次约束权重提升；本轮未另外压缩该调度。不能把所有质量差异仅归因于少走一步。
- ≥5nm包含恰好5nm；小违例严格为0<残差<5nm。最终使用原始双倍DBU几何，由独立主机整数检查器复核。
- 增加线长是trim模型绝对位移总和；该输入只有向外移动，等于净延长量。实际OpenDB布线未写回，每个样本核对原长89,786.472µm保持不变。
- 同一输入为 `flow/results/asap7/ibex/base/5_2_route.odb`，DBU/µm=1000，M2–M7，共332,664节点、437,360边。
- NVIDIA GeForce RTX 5060 Laptop GPU / CUDA Toolkit 12.9.1。命令耗时包含建图、优化、CSV和最终检查，排除read_db和预热；日志/CSV先写Linux /tmp，再归档。
- 不删除慢样本，保留三次原始时间。例如60轮有2592.386ms样本，中位数仍为1607.634ms。各阶段中位数不机械相加。

## 探索和验证

单次探索19个预算：100、80、75、70、65、60、50、45、40、35、32、30、28、26、25、15、10、5、1轮。随后固定表中8个预算，三次交替复测，同时测cooperative与20W的LEO对照。
探索用于筛选，速度结论只取confirm的三次结果。所有原始样本均保留，不以单次时间作结论。

本轮沿用前轮构建的CUDA模块，模块及ODB哈希与上一轮EMA权重实验一致，无需修改/重新编译C++。100轮基线所有636行的非计时列均与前轮完全相同。
汇总脚本逐样本验证：质量可重复、最终结果相对同次修复阶段的残差/线长不增，以及每层仅一次最终坐标下载；全设计下载2,661,312bytes。
最大残差及残差总量另外从final行提取并核对三次一致，见 `tradeoffs.csv/json`。
