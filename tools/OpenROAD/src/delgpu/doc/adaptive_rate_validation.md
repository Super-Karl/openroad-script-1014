# 动态学习率：平滑降速与收敛反馈

日期：2026-10-15。输入仍为 `flow/results/asap7/ibex/base/5_2_route.odb`，
GPU 为 RTX 5060 Laptop。固定 `max_step=0.25W`、`jump_offset_nm=35`、
`max_backtracks=0`，GUI/建图校验关闭。比较各自预算末态，不恢复历史最佳快照，
不运行 LP/MIP，也不修改实际布线。

## 调整规则

新增 `-learning_rate_mode adaptive`，原 `linear` 模式及默认值继续保留。
每层维护一个独立控制器，起始比例 η_start，下限 η_min：

```text
u = (iteration - 1) / (max_iterations - 1)
ceiling = eta_min + (eta_start - eta_min) * (1 + cos(pi*u)) / 2
eta = min(previous_eta, ceiling)
```

单轮预算仅用初值。反馈只影响下一轮，且不低于下限：

- 连续两轮普通梯度及扰动均未接受候选：η 乘 0.8。
- 每八轮检查一次；若规则能量下降不超过约 1%，且 ≥5nm 数量没有减少：η 乘 0.85。
- 反馈降速后重新开始观察窗口；比例只减不增，末轮达到下限。

控制器使用不乘惩罚权重 lambda 的 `rule_energy`，避免每 25 轮 lambda 改变导致
加权能量跳变而被误判为停滞。新增 `gradient_accepted` 单独记录梯度/扰动是否接受；
CPU 跨势垒跳跃成功不能替代这个标志。

普通梯度位移上限仍为 `0.25W × η`，最终强制裁剪到移动域。
CPU 的 ≥5nm 停滞资格、分量内有序修复、移动后立即清零以及 35nm 跳跃均保持原规则。
所有反馈来自已有轮末摘要，不增加 GPU 候选、归约、坐标下载或新的回溯。

`learning_rate_end` 在动态模式下是下限，要求 `0 < end <= initial`。
省略末值时使用 `min(initial, 0.5)`；在线性模式省略末值仍表示固定比例。
CSV 记录实际 η、有效上限、`gradient_accepted`、累计 `lr_feedback_reductions`
以及 `rule_energy`，可查看各层不同的降速时机。

## 参数筛选

扫描 100/125/150/200 轮及六组初值/下限，共 24 个配置。
表格为各预算末态的 ≥5nm 数量，不是同一条 200 轮轨迹的中间记录：

| 轮次 | 1.5→0.5 | 1.5→1 | 2→0.5 | 2→1 | 3→0.5 | 3→1 |
|---|---:|---:|---:|---:|---:|---:|
| 100 | 160 | 122 | 130 | 156 | 163 | 159 |
| 125 | 105 | 104 | 103 | 122 | 115 | 157 |
| 150 | **64** | 92 | 94 | 104 | 121 | 149 |
| 200 | **62** | 89 | 76 | 112 | 76 | 119 |

控制器的余弦上限依赖总预算，150 和 200 轮并非相同前缀。
单纯提高初值并未改善本例的最终质量，1.5→0.5 更合适。

## 三次交替复测

在没有其他 GPU 实验同时运行时，先进行 GPU 200 轮预热，再交替运行五种配置，
各三次。每次重新建图、从零位移初始化。三次质量结果一致。

| 方法 | 轮次 | 起始→末值/下限 | ≥5nm 数量 | trim 延长量（µm） | 优化耗时中位数（s） |
|---|---:|---|---:|---:|---:|
| 固定 | 200 | 1→1 | 83 | 2764.297657 | 2.654367 |
| 上一版线性 | 150 | 1.5→1 | 85 | 2716.864825 | 1.981703 |
| 同起止值线性对照 | 150 | 1.5→0.5 | 77 | 2713.768792 | 1.938264 |
| **动态，推荐** | **150** | **1.5→0.5** | **64** | **2693.708982** | **1.917090** |
| 动态，更长预算 | 200 | 1.5→0.5 | 62 | 2701.158861 | 2.693198 |

推荐的 150 轮动态配置相比固定 200 轮：

- ≥5nm 数量少 19 条，83→64，约减少 22.9%。
- 优化耗时减少约 27.78%，2.654→1.917 秒。
- trim 延长量减少 70.588675µm，约 2.55%。

相同 150 轮、相同起止比例下，动态策略比线性对照少 13 条，运行时间相近，
延长量也更低。该对照比较的是余弦上限与反馈组合的整体效果，未单独分离二者贡献。
动态 200 轮再减少 2 条，但比推荐 150 轮增加约 0.776 秒，并非当前效率优先选择。

三次优化耗时（ms）：

- 固定 200：2654.367 / 2649.151 / 2680.060。
- 上一版线性 150：1980.792 / 1981.703 / 2040.965。
- 同起止值线性 150：1928.451 / 1972.511 / 1938.264。
- 动态 150：1837.484 / 1917.090 / 1921.512。
- 动态 200：2693.198 / 2696.698 / 2664.733。

优化耗时含优化初始化、循环、CSV/日志、最终下载和独立主机检查；
不含读库、建图、CUDA 上下文初始化或 LP/MIP。
完整命令（另含建图等）耗时中位数依次为
3.190949 / 2.474086 / 2.471367 / 2.434139 / 3.197783 秒。
当前输入的绝对 trim 位移与朝外净延长量相同；这些数字是模型增量，
实际布线未写回，普通布线长度在实验前后保持 89,786,472 DBU。
约束图残差不是实际布线 DRC。

## 使用与复现

```tcl
delgpu -gui 0 -max_iterations 150 -max_step 0.25 -jump_offset_nm 35 \
  -max_backtracks 0 -learning_rate_mode adaptive \
  -learning_rate 1.5 -learning_rate_end 0.5
```

ORFS 启动脚本：

```bash
./dev-openroad.sh optimize --gui 0 --iterations 150 \
  --learning-rate-mode adaptive --learning-rate 1.5 --learning-rate-end 0.5
```

扫描与复测：

```bash
./dev-openroad.sh run -no_splash -exit tools/OpenROAD/src/delgpu/scripts/benchmark_adaptive_rate.tcl
DELGPU_ADAPTIVE_PHASE=confirm \
DELGPU_ADAPTIVE_CASES='{fixed200 linear 200 1 1} {linear150 linear 150 1.5 1} {matched150 linear 150 1.5 0.5} {adaptive150 adaptive 150 1.5 0.5} {adaptive200 adaptive 200 1.5 0.5}' \
  ./dev-openroad.sh run -no_splash -exit tools/OpenROAD/src/delgpu/scripts/benchmark_adaptive_rate.tcl
python3 tools/OpenROAD/src/delgpu/scripts/summarize_adaptive_rate.py
```

`DELGPU_ROUTE_DB`、`DELGPU_BENCHMARK_DIR` 可覆盖输入及输出目录。
CSV、日志和机器可读汇总位于
`flow/reports/asap7/ibex/base/delgpu_adaptive_rate/`。
汇总脚本检查每轮实际比例单调、有界、不超过余弦上限、最终达到下限，
并核对原 lambda 调度和各次末态质量一致性。

验证包括 67 项单元测试、完整宿主与模块构建、非 CUDA stub 编译、参数校验，
以及动态模式下 GUI 图像更新与关闭显示检查。
