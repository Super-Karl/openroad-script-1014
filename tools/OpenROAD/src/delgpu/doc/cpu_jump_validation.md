# CPU 跳跃规则与关闭回溯的 200 轮实验

日期：2026-10-15。输入 `flow/results/asap7/ibex/base/5_2_route.odb`，
GPU 为 RTX 5060 Laptop，参数 `200 / 0.25W / 35nm`，GUI 和建图校验关闭。
只比较连续第 200 轮末态，不恢复历史快照，不运行 LP/MIP。

## 本次实现

GPU 修复采用原版 CPU 的规则：旧、新残差均 ≥5nm，连续三轮端点无可见移动；
每轮检查，B/C 跳到势垒中点另一侧 `midpoint ±35nm`，保持度数分摊、移动域容量、
机器精度容差和双端点提交校验。成功后立即清零实际移动端点的全部关联计数。
不再投影 A/B/C 到最近合法区间，不修复小于 5nm 的残差。

主机初始化时建立无向连通分量，把各分量的边按原编号保存。GPU 一线程拥有
一个活跃分量，在分量内保持 CPU 的原边顺序；不同分量之间无共享节点，可以并行。
停滞检测、修复、梯度和归约均在 GPU 执行，不把修复工作搬回 CPU。

GPU 新参数 `-max_backtracks` 表示失败后将步长减半重试的次数：

- `0`：默认，每种尝试仅评估初始步长，取消步长减半重试。
- `7`：每种尝试最多 8 个候选步长，对应旧 GPU 的预算。
- `19`：每种尝试最多 20 个候选步长，对应原 CPU 的预算。

三种模式都保留全层能量下降检查和两种确定性扰动。初始方向失败时，扰动仍可
各尝试一次；零次回溯模式每层每轮最多三个候选。失败候选不提交，硬移动域始终生效。
CPU 参考不接受该参数，保持原版 20 个候选步长的实现。

去掉历史最佳快照的保存/恢复和对应坐标缓冲；CPU/GPU 均返回最后一轮。
CSV 最后一行类型从 `best` 改为 `final`；每轮统计仍为 `iteration`。
≥5nm 判断不再加入 `1e-6 DBU` 的边界偏移。

## 三次交替测量结果

一次 GPU 完整回溯预热后，在同一进程交替运行四种模式，每种三次。
每次均重新建图和从零位移初始化；数据库和实际布线不修改。
CSV 开启，六层均完成 200 轮。各模式的三次违例数和延长量一致。

| 方法 | trim 延长量（µm） | 第 200 轮 ≥5nm 数量 | 优化耗时中位数（s） | 循环耗时中位数（s） |
|---|---:|---:|---:|---:|
| CPU 参考，20 个候选步长 | **2757.084160** | **90** | **10.197858** | 10.163007 |
| GPU，不减半重试（默认） | **2764.297657** | **83** | **2.606924** | 2.479632 |
| GPU，7 次减半重试 | 2757.134672 | 90 | 3.521841 | 3.399670 |
| GPU，19 次减半重试 | 2757.084160 | 90 | 3.068202 | 2.938473 |

优化耗时含优化初始化、200 轮、日志/CSV、最终坐标下载和独立主机检查；
不含数据库加载、建图、CUDA 上下文初始化或后处理。
循环耗时仅统计各层循环之和，包含每轮统计和日志/CSV。
完整命令耗时另含建图等调用开销，其中位数为 CPU 11.455847s、GPU0 3.188175s、
GPU7 3.982290s、GPU19 3.529012s。个别样本的建图/命令耗时波动较大，
完整命令计时不能与优化阶段计时混用。

三次优化耗时（ms）：

- CPU：10059.094 / 10197.858 / 10737.328。
- GPU0：2586.672 / 2690.957 / 2606.924。
- GPU7：3529.491 / 3500.308 / 3521.841。
- GPU19：3021.939 / 3188.631 / 3068.202。

默认 GPU 对 CPU 的优化阶段加速约 **3.912 倍**，≥5nm 数量少 **7 条**，
trim 延长量多 **7.213498µm（0.2616%）**。
关闭回溯比 GPU 完整回溯节省约 **15.03%** 优化时间。
这是当前单个设计的结果，不保证取消回溯在其他设计上也减少违例。

保留七次重试在本例反而比完整回溯慢：GPU0/7/19 的全程候选数分别为
2650 / 7557 / 4482。较早放弃普通方向可能转入更多扰动尝试，后续轨迹也随之改变。
回溯上限与总耗时不一定单调。

## 线长和违例口径

`extent_um = Σ|trim 位移| / DBU` 是原版 DEL 的连续阶段口径。
新增 `wire_extension_um = Σ(high_end ? 位移 : -位移) / DBU`，按端点朝外的方向
计算净延长量。当前输入的移动域只允许向外移动，各模式这两个数相同。
它们表示 trim 模型的延长量，未做写回布线后的金属合并和线段测量。

实际 OpenDB 普通布线长度在实验前后均为 **89,786,472 DBU**（89,786.472µm），
实际已写回的线长增量为 **0**。当前算法输出覆盖层位移，不能把模型延长量
误称为已经修改后的实际线长。

违例是约束图上到合法区间的残差达到 5nm 的边数，包含等于 5nm；
它不是实际布线 DRC 报告。GPU0 各层为 M2=51、M3=13、M4=4、M5=0、M6=15、M7=0；
CPU/GPU19 为 71 / 7 / 0 / 0 / 12 / 0。
总数量减少，但部分层的 ≥5nm 数量增加，因此不能仅根据合计断言逐层更优。

## 一致性与验证

CPU 后端仍使用与原版 `del` 一致的 `Optimizer.cpp` 和 `StallRepair.cpp`。
原版连续第 200 轮的 90 条和 2757.084160µm 与本次 CPU 参考一致；
这里的 CPU 计时是该参考后端的优化计时，不包含原版 `del` 自动 LP/MIP 阶段。

GPU19 三次各 6 层 ×200 轮，≥5nm 数量和跳跃次数全部与 CPU 对应记录一致；
第 200 轮的延长量也一致。GPU0 仅跳跃规则保持一致，梯度轨迹因关闭回溯而改变。
浮点归约顺序仍不提供普遍逐位一致保证。

CUDA 模块与完整 GUI 宿主构建通过，非 CUDA stub 构建通过；60 项单元测试通过，
覆盖共享端点即时清零、分量独立、多规则图 200 轮 CPU/GPU 对比、无回溯能量检查、
硬移动域和 DBU 单位。offscreen GUI 回归确认中间图像更新以及关闭显示清除覆盖层。
命令参数检查通过，默认零回溯复测确认第 200 轮 83 条。
