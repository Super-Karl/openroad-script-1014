# 学习率与缩短迭代预算实验

本文记录固定/线性调度。后续增加的按状态反馈调度及对比见
[动态学习率实验](adaptive_rate_validation.md)。

日期：2026-10-15。输入为 `flow/results/asap7/ibex/base/5_2_route.odb`，
RTX 5060 Laptop。所有实验固定 `max_step=0.25W`、`jump_offset_nm=35`、
`max_backtracks=0`；GUI、建图校验和 LP/MIP 均关闭，比较各自预算末态。

## 学习率的定义

新增 `-learning_rate`（默认 1）和可选 `-learning_rate_end`。
原有 lambda 是规则惩罚权重，仍按每 25 轮 10/20/40/80 增长；
新增比例 η 乘在普通梯度更新的移动距离上，不改变目标函数权重。

设总预算为 T，当前轮为 t，η 的线性调度为：

```text
eta[t] = (1 - u) * eta_start + u * eta_end
u = (t - 1) / (T - 1)
```

T=1 时使用初值。省略末值表示固定学习率，η=1 的路径保持原更新公式。
学习率在原梯度方向的全层归一化之后乘入，避免先放大梯度再归一化导致比例失效。
普通候选（位移按层线宽 W 归一化）为：

```text
p = 原有经度数预条件和移动域裁剪的方向
S = max(abs(p)) > max_step ? max_step / max(abs(p)) : 1
cap = max_step * eta[t]
trial = clamp(current + clamp(2^(-backtrack) * eta[t] * S * (p + jitter),
                              -cap, cap), low, up)
```

例如 η=1.5 时梯度位移上限为 0.375W，η=3 时为 0.75W。
最后强制满足硬移动域，候选仍要求整层能量下降。
CPU 停滞资格、分量内原边顺序、即时清零以及中点另一侧 35nm 跳跃不变；
跳跃不受普通梯度步长上限限制，也不乘学习率。

仅 GPU 接受这两个选项，CPU 参考继续使用原更新方法。
CSV 新增 `learning_rate` 和 `effective_max_step_w` 列，日志也记录实际比例。
默认仍是 200 轮、固定 η=1，便于继续复现前一版基线。

各比例先运行 200 轮，从同一轨迹提取中间轮次用于筛选，表中均为 ≥5nm 数量。

## 交替三次复测

在没有其他 GPU 实验同时运行时，先预热 η=1 的 200 轮，再交替运行以下五种配置，
每种三次。每次重新建图，从零位移开始。各配置的三次违例数和延长量一致。

| 轮次 | 学习率 | ≥5nm 违例 | trim 延长量（µm） | 优化耗时中位数（s） | 比 200 轮省时 |
|---|---|---:|---:|---:|---:|
| 200 | 固定 1（基线） | **83** | 2764.297657 | **2.664178** | — |
| 150 | 固定 1（对照） | 115 | 2757.966904 | 1.933327 | 27.43% |
| 125 | 固定 1（对照） | 123 | 2753.968850 | 1.563488 | 41.31% |
| 150 | **1.5→1** | **85** | **2716.864825** | **1.991256** | **25.26%** |
| 125 | **3→0.5** | **90** | **2753.287975** | **1.610964** | **39.53%** |

150 轮调度相比同预算固定学习率减少 30 条违例，比 200 轮基线多 2 条，
trim 延长量少 47.432832µm（约 1.716%）。这组更接近原质量。
125 轮调度相比同预算固定学习率减少 33 条，比 200 轮基线多 7 条，
trim 延长量少 11.009682µm。它提供更短运行时间。
二者均未达到 200 轮基线的 83 条，不能声称同时获得更低违例数和更短时间。

三次优化耗时（ms）：

- 200 固定：2602.644 / 3086.193 / 2664.178。
- 150 固定：1898.426 / 1970.424 / 1933.327。
- 125 固定：1553.159 / 1563.488 / 1572.363。
- 150 调度：1967.034 / 2001.623 / 1991.256。
- 125 调度：1606.863 / 1647.850 / 1610.964。

优化耗时含优化初始化、循环、CSV/日志、最终下载与独立主机检查；
不含读库、建图、CUDA 上下文初始化和 LP/MIP。
包含建图等调用开销的命令耗时中位数依次为
3.117365 / 2.409378 / 2.027320 / 2.446475 / 2.105681 秒。
首个配置有一个较慢样本，全部时间列在这里，结论使用中位数。

延长量是 trim 模型的位移延长，当前输入的绝对位移和朝外净延长量相同。
实际布线没有写回，普通布线长度在所有实验前后仍为 89,786,472 DBU。
违例计数使用约束图的残差 ≥5nm，不是实际布线 DRC。
这些参数在当前 ibex 输入上筛选并复测；重复测量验证运行稳定性，
不代表已经在独立设计上验证泛化效果。

## 使用与复现

较接近原质量的配置：

```tcl
delgpu -gui 0 -max_iterations 150 -max_step 0.25 -jump_offset_nm 35 \
  -max_backtracks 0 -learning_rate 1.5 -learning_rate_end 1.0
```

较短预算：

```tcl
delgpu -gui 0 -max_iterations 125 -learning_rate 3 -learning_rate_end 0.5
```

ORFS 启动脚本：

```bash
./dev-openroad.sh optimize --gui 0 --iterations 150 --learning-rate 1.5 --learning-rate-end 1
```

学习率扫描和复测：

```bash
./dev-openroad.sh run -no_splash -exit tools/OpenROAD/src/delgpu/scripts/benchmark_learning_rate.tcl
DELGPU_LR_PHASE=anneal ./dev-openroad.sh run -no_splash -exit tools/OpenROAD/src/delgpu/scripts/benchmark_learning_rate.tcl
DELGPU_LR_PHASE=confirm \
DELGPU_LR_CASES='{baseline200 1 200} {fixed150 1 150} {fixed125 1 125} {anneal150 1.5 150 1} {anneal125 3 125 0.5}' \
  ./dev-openroad.sh run -no_splash -exit tools/OpenROAD/src/delgpu/scripts/benchmark_learning_rate.tcl
python3 tools/OpenROAD/src/delgpu/scripts/summarize_learning_rate.py
```

`DELGPU_ROUTE_DB` 可切换输入，`DELGPU_BENCHMARK_DIR` 可指定输出目录，
汇总脚本接受同一个目录作为参数。
本次 CSV、日志、汇总与 GUI 截图保存在
`flow/reports/asap7/ibex/base/delgpu_learning_rate/`。

验证包括 64 项单元测试（步长缩放、硬域裁剪、每轮比例覆盖、无效值/溢出、
原 CPU 对比等），以及完整宿主和模块构建、非 CUDA stub 编译、Tcl 参数检查，
GUI 动态学习率下的图像更新/关闭显示检查。
汇总脚本还逐轮核对实际 η、有效上限及原 lambda 调度。
