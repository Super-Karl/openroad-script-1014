# 安全回缩优化：整组协同与合并组平移

2026-10-15。参考原版 DEL `src/del/src/optimize/Postprocess.cpp` 的 `polish()`，
已将 GPU 默认回缩升级为 `cooperative`。连续迭代和冲突修复参数保持不变。

## 原方法为什么停得早

原方法固定其他端点，只回退当前端点，逐条保证残差不增加。
若几个端点已合并、或者相互间距刚好卡在合法边界，单独退谁都可能破坏约束。
因此即使有整组一起退的空间，单点回缩也会停止。

DEL 的 LP 会固定每条边当前最近的合法分支，用当前残差适当扩展区间，
在不增加每条边残差的情况下，同时优化整个分量的线性延长量目标。
真实测试图的移动域均向外，DEL 的带方向延长量目标与绝对位移总量相同。
GPU 新实现借鉴了“共同移动”和“总量优化”的思路，保留整数坐标，仍不调用 LP/MIP。

## 新增两种共同移动

先运行原单点回缩；只有单点停滞后，才尝试下面两种移动，避免打断原有下降路径。

**同时向原始位置回退。** 为每个节点计算可以回退的最大整数距离：
同向节点间的约束变成 `本节点回退量 ≤ 邻居回退量 + 间距余量`；
相反方向的节点，先确定性分配共同可用的间距余量，再传播差分上界。
传播时坐标冻结，使用两个回退量缓冲交替计算。最多传播 128 轮，每 8 轮读取一次标量。
最后对所有原始边做精确残差检查：预算内未通过检查的分量不提交，其余分量同时回退。
这可以处理多个端点互相阻挡、必须一起移动的情况。

**已合并的整组平移。** 一部分场景还需要允许某个端点伸长，换取更多端点缩短。
例如三个 trim 已合并，原始位置不同，当前位移为：

```text
                     端点 A       端点 B       端点 C       绝对位移总量
当前位移：           +20          +20          -30          70 DBU
整组向左平移 20：      0            0           -50          50 DBU
```

三个端点的实际位置一起移动，相互距离保持不变。
C 延长了 20 DBU，但 A、B 合计缩短了 40 DBU，总量减少 20 DBU。
这也是只允许每个节点单独向原点回退时无法发现的解。

GPU 为当前固定分支下相对位移不能变化的节点构建合并组，
求出整组允许平移区间，再选择最接近位移中位数的平移量，最小化组内绝对位移总量。
每个分量每轮只选择一个最优组，不同分量并行，提交前再次检查所有关联边和硬移动域。
合并组超过 256 个节点时跳过这类平移候选，控制单个 GPU 线程的最坏工作量；
这些节点仍可参与原单点回缩和前一种整组回退。

两种方法都要求总延长量严格下降，每条边的残差不增加。
整组平移可以使个别节点的绝对位移增加；约束检查和目标比较以完整方案为单位。
GPU 最终统计继续由独立 CPU 整数检查器核对，<5nm 违例统计保持不变。

## 使用

```tcl
delgpu -gui 0                                     ;# 默认 cooperative，最多 8 次回缩扫描
delgpu -gui 0 -post_retract_mode single            ;# 原单点回缩
delgpu -gui 0 -post_retract_mode cooperative       ;# 新版
delgpu -gui 0 -post_retract_sweeps 16              ;# 更高搜索预算
delgpu -gui 1                                     ;# 显示新版最终结果
```

启动脚本对应 `--post-retract-mode single|cooperative` 和 `--post-retract-sweeps`。
`-post_retract_sweeps 0` 仍完全关闭回缩；`-postprocess 0` 关闭整个后处理。
关闭 GUI 时不增加中间坐标下载或绘图，仅增加设备内缓冲和标量摘要。
日志新增 `cooperative_moves`、`group_moves`（均为累计移动节点次数）以及 `propagation_rounds`。

## 同一修复末态的对照

ASAP7 IBEX，RTX 5060 Laptop，CUDA 12.9.1，关闭 GUI 与重复建图校验。
连续阶段仍为 150 轮、0.25W、35nm、adaptive 1.5→0.5。
预热后交替测量四种配置，各三次，逐层确认 `repaired` 行的计数、最大/总残差和延长量完全相同。
每次均重新运行，不沿用上一种方法的位置。质量三次一致，以下时间均为中位数。

| 方法 | ≥5nm | 0<残差<5nm | 延长量 µm | 回缩 ms | 后处理总 ms | 优化总 ms | delgpu 命令 ms |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 原单点，8 次上限 | 36 | 48 | 2632.331 | 6.344 | 102.535 | 1938.550 | 2420.710 |
| 新版，8 次上限（默认） | **36** | **48** | **2607.572** | **23.955** | **123.667** | **1967.562** | **2421.630** |
| 新版，16 次上限 | 36 | 48 | 2607.525 | 28.708 | 128.474 | 2000.242 | 2502.610 |
| 新版，32 次上限 | 36 | 48 | 2607.525 | 28.065 | 125.332 | 1992.438 | 2476.589 |

默认新版相对原回缩再减少 **24.759µm（约 0.94%）**，每条边残差不增加，
最终仍为 84 条严格违例，其中 36 条 ≥5nm、48 条 <5nm。
最大残差仍为 16nm、总残差仍为 432nm。
回缩自身增加约 17.6ms，完整优化总耗时中位数增加约 29.0ms（约 1.5%）。
命令耗时还含建图且受波动影响，不能用两组命令时间差代替设备阶段的额外开销。
16 次只再减少 0.047µm、32 次无进一步收益，因此默认保持 8 次。

原方案仅增加“所有节点朝原点一起退”时，单次实验为 2625.423µm；
加入允许少数端点伸长的合并组平移后降到 2607.572µm。
该消融值仅为一次实验，不用它比较性能。

这仍是有预算的局部优化，固定当前分支、限制合并组大小，也不执行完整 LP/MIP，
不能据此断言达到 DEL LP 或全局最优。仍可进一步研究剩余难分量。

- CUDA 宿主/模块、CPU-only entry 构建与 76 个单元测试通过。
