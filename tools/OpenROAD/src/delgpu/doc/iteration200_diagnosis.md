# 第 200 轮 ≥5 nm 残差差距诊断

本文记录旧投影修复版本的诊断。当前版本已采用 CPU 跳跃规则、分量内有序修复，
并默认关闭步长减半回溯；更新结果见 [跳跃与回溯实验](cpu_jump_validation.md)。

日期：2026-10-15。输入为 `flow/results/asap7/ibex/base/5_2_route.odb`，
参数为 `-max_iterations 200 -max_step 0.25 -jump_offset_nm 35`，GUI 关闭。
只读取 CSV 的 `stage=iteration, iteration=200`，不读取 `best`，不包含 LP/MIP。

结论：当前 GPU 的停滞修复改变了 CPU 的算法语义。主要差距来自合法区间投影
与跨势垒跳跃的差异，以及与之配套的门槛、触发频率和计数清零规则。
本次输入上，回溯上限由 20 次减为 8 次不是主要原因；严格对齐修复后，GPU 可以复现
CPU 全部 200 轮的 ≥5 nm 数量和跳跃次数。

## 统一统计口径

| 层 | CPU 第 200 轮 ≥5 nm | 当前 GPU 第 200 轮 ≥5 nm |
|---|---:|---:|
| M2 | 71 | 715 |
| M3 | 7 | 135 |
| M4 | 0 | 7 |
| M5 | 0 | 2 |
| M6 | 12 | 57 |
| M7 | 0 | 0 |
| 合计 | **90** | **916** |

差距为 826 条，约 10.18 倍；M2/M3 占新增残差的 93.46%。
原版 `del` 的连续第 200 轮也是 90 条。`delgpu -backend cpu` 的
`Optimizer.cpp`、`StallRepair.cpp` 经命名空间替换后与原版源码一致。

之前记录的 CPU 577、GPU 1,036 是历史最佳快照的 ≥5 nm 数量。
两个后端按照总冲突数选快照，当前 GPU 总冲突统计还排除 ≤1e-6 DBU 的数值残差。
这样的选择标准并不保证 ≥5 nm 数量最少，也不代表第 200 轮状态。
本报告全部控制实验均使用第 200 轮状态。

## 代码中的实际差异

| 规则 | 原版 CPU | 当前 GPU |
|---|---|---|
| 停滞资格 | 旧、新残差均 ≥5 nm，端点连续 3 轮无可见移动 | 旧、新残差均 >1e-6 DBU，连续 3 轮无可见移动 |
| 修复检查 | 每轮检查达到停滞条件的边 | 仅全局轮数为 3 的倍数时检查 |
| 修复目标 | B/C 禁区势垒中点的另一侧，`midpoint ±35 nm` | A/B/C 优先投影到最近、可达的合法区间 |
| 35 nm 参数 | 决定每次跨势垒目标 | 只有找不到可达合法目标时才用于 B/C 备用跳跃 |
| 调度顺序 | 原边顺序 | 按颜色顺序，同色边并行 |
| 清零时机 | 成功移动后立即清零移动端点的所有关联边 | 所有颜色结束后才清零，节点可在同轮被不同颜色重复移动 |
| 每次尝试的回溯上限 | 20 | 8 |

CPU 位置：`src/del/src/optimize/StallRepair.cpp` 的 `arcViolated`、
`jumpAcrossBarrier`、`repairStalled`，以及 `Optimizer.cpp` 的 `gradientStep`。
GPU 位置：`TrimOptimizer.cu` 的 `stallKernel`、`repairKernel`、
`Impl::step`；快照恢复位于 `RunOptimization.cpp`。
原 `plan.md` 的分量内有序跳跃设计与 CPU 一致，当前实现采用了文末记录的性能改动。

两种修复都会使用硬移动域、按端点度数分摊位移，但这并不足以保证算法相同。
最近合法区间投影倾向选择移动代价最小的边界；CPU 刻意跨过势垒中点，改变后续
下降所在的区间。修复一条边也会改变共享端点的其他约束，因此局部合法并不意味着
全图的 ≥5 nm 残差数下降。

## 控制实验

使用临时诊断补丁给 GPU 添加运行时实验配置；所有配置使用相同输入、初始化、
lambda 调度、200 轮预算和参数。GPU 梯度、移动和归约仍在 GPU 执行。
只有 `aligned_ordered` 用单个 GPU 线程扫描整层边，以检验 CPU 顺序语义，
这是诊断实现，不能把其调度方式直接作为生产性能方案。

| 实验配置 | 相对当前 GPU 的变化 | 第 200 轮 ≥5 nm |
|---|---|---:|
| `cpu` | CPU 参考 | **90** |
| `baseline` | 当前 GPU | **916** |
| `backtrack20` | 只将回溯上限恢复到 20 | **916** |
| `threshold5` | 只将停滞资格改为 ≥5 nm | **892** |
| `barrier_target` | 只把投影目标改为 CPU 跳跃，仍保留微小残差触发和原调度 | **6,332** |
| `projection_aligned` | 5 nm 门槛、每轮修复、每个颜色后清零、20 次回溯，保留投影 | **893** |
| `repair_aligned` | CPU 跳跃、5 nm 门槛、每轮修复、每个颜色后清零，保留边着色和 8 次回溯 | **86** |
| `aligned_colored` | 在上一项基础上恢复 20 次回溯 | **86** |
| `aligned_ordered` | CPU 修复全部规则、原边顺序和立即清零、20 次回溯 | **90** |
| `restored` | 撤回临时补丁、重编译后复测当前 GPU | **916** |

证据说明：

1. CPU/GPU 前两轮的 ≥5 nm 数量相同；首次差异在第 3 轮，恰好开始停滞修复。
   该轮 CPU 跳跃 5,239 次，当前 GPU 修复 9,346 次。
2. 对齐门槛、频率、清零和回溯，但继续投影仍有 893 条；改用 CPU 跳跃后有 86 条。
   这组对照直接支持修复目标是主要差距来源。
3. 不能只替换跳跃公式：对微小残差频繁作大幅跨势垒移动的 `barrier_target`
   反而有 6,332 条。门槛、调度和清零必须一起匹配。
4. `aligned_ordered` 与 CPU 的 6 层 × 200 轮共 1,200 对记录，≥5 nm 数量
   和跳跃次数均没有差异。CSV 精度下最大能量差约 1e-6，不能解释当前 10 倍的差距。
5. 当前 GPU 200 轮共修复 2,409,680 次，CPU 为 14,003 次。改为 5 nm 门槛后
   修复次数降到 32,565，但最终仍有 892 条。大量微小残差修复增加反复移动，
   是问题的一部分；它不能单独解释剩余差距。

当前 GPU 后期轨迹还显示投影和梯度更新反复改变冲突状态：

| 轮次 | 总冲突 | ≥5 nm | 修复次数 |
|---|---:|---:|---:|
| 195 | 40,470 | 998 | 42,017 |
| 196 | 79,989 | 941 | 0 |
| 197 | 81,697 | 896 | 0 |
| 198 | 51,665 | 1,043 | 32,614 |
| 199 | 82,342 | 961 | 0 |
| 200 | 82,663 | 916 | 0 |

第 198 轮修复减少总冲突，却增加 ≥5 nm 数量，说明两个评价指标存在实际冲突。

## 后续实现方向

若以 200 轮末态的 ≥5 nm 数量为主要质量指标，应首先恢复 CPU 的停滞资格、
跨势垒目标、每轮检查和成功后立即清零语义。边着色对齐版本在本次输入得到 86 条，
说明在保留并行的情况下可以消除当前的大差距；这是单个设计的实验结果，
仍需独立设计和重复计时验证质量与性能，不能声称普遍优于 CPU。

若要求修复算法语义严格一致，按 `plan.md` 的无向连通分量划分，在分量之间并行，
分量内部保留原边顺序和立即清零。不要用整层单线程诊断核作为生产实现。
如果最终仍恢复历史快照，应把 ≥5 nm 数量放到选择标准首位，并明确区分
`iteration=200`、历史最佳快照和 LP/MIP 后处理结果。

本次没有修改生产算法；临时补丁已撤回，原版 GPU 重编译及 200 轮复测通过。
现有测试覆盖单步和局部约束正确性，没有保证真实图的 200 轮修复轨迹与 CPU 一致。
