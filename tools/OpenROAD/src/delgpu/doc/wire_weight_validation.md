# 只提高迭代线长权重的对照实验

2026-10-16。基于 `main` / `50b31e7`；不引入 EMA、候选搜索、迭代回缩或其他优化阶段。
此前的 `tmp-gpu-ema` / `fc0016e` 未改动。本次只把原有目标中的线长系数从固定
`0.01` 改为 GPU 参数 `-wire_weight`，默认仍为 `0.01`。

实测收益有限：权重 `0.05` 保持最终违例 36/48，将增加线长减少 **4.046µm（0.155%）**；
命令时间中位数增加约 1.15%，不能据此认为更快。权重继续增加能明显压低连续阶段线长，
但会增加残差和后处理补偿，最终线长不单调下降。这组结果不足以支持修改默认值。

## 当前移动规则与延长来源

每层独立优化，坐标为沿轨位移除以本层线宽 `W`，记为 `z_i`。现有目标为：

\[
 E_\lambda(z)=\alpha\sum_i(\sqrt{z_i^2+0.01^2}-0.01)
                +\lambda\sum_e\phi_e(d_e^0+z_t-z_s).
\]

`0.01` 的平滑尺度保持不变；本次仅调整外面的 `α`。这是宽度归一化的线长代价，
每层内对应总绝对位移；原始输入的域只允许向外移动，因此绝对位移与净延长量相等。

普通移动的节点方向为 `-gradient / (1 + degree)`，先投影到硬移动域，再按全层最大方向
统一缩放到 `max_step`，乘学习率。若能量未下降，尝试两种固定 `±0.01` 扰动；
默认没有步长减半。默认上限为 `0.25W × learning_rate`，学习率自适应从 1.5 降至 0.5。
约束权重每 25 轮从 10 递增至 20、40、80。线长权重影响节点方向、候选能量、接受检查
和统计能量；只修改其中一处会使方向与接受条件不一致，本实现同步修改三处。

规则势能和残差计数不是同一个目标：A / 负距离 B 使用下界平方罚；B/C 的禁区使用
四次势垒，在区间中点导数为零，区间外势能为零。B 的合法集合包含孤立点 0，
C 的合法集合也包含孤立点 0。靠近平衡点时，较大的线长梯度可以用少量规则残差换取
更短的线长。对单个 A 约束且仅一个端点可动、位移远离零的简化情况，平衡残差约为
`αW / (2λ)`；这解释了为何提高 α 后小正残差会增多，不能把连续线长下降直接视为成功。

停滞检查要求前后两态残差均 ≥5nm，端点按 DBU 取整后连续三轮不动。B/C 跳跃使用
`midpoint ± 35nm`，按端点度数分摊，并立即清零移动端点的关联停滞计数。跳跃遵守硬域，
但不受普通最大步长和能量下降检查限制；它既不直接选最近合法边界，也不检查关联规则的
总线长收益。故提高 α 不能限制跳跃本身：强回拉与固定跳跃可能相互抵消。
这一结构性限制来自代码；本实验没有修改跳跃规则，也没有把每个微米的差异逐项归因于它。

不必要延长的可能来源是：较弱的回拉使普通移动后的冗余量保留；全层能量接受允许局部
延长换取其他边的改善；固定势垒跳跃可以产生较大位移；局部非凸区间选择会锁定较长解。
提高 α 主要影响前两项，无法单独解决后两项。

## 输入与测量口径

- 输入：`flow/results/asap7/ibex/base/5_2_route.odb`，DBU/µm=1000，M2–M7。
- SHA256：`381e1ddc86e2e9f1017fcd1094d11b969efa8fee40d32c50ff6d0f082ab4d744`。
- 图：332,664 节点，437,360 条边；初始违例 104,657 条。
- NVIDIA GeForce RTX 5060 Laptop GPU，CUDA Toolkit 12.9.1，Bazel GUI 宿主。
- 所有性能实验 `gui=0`、`verify=0`；150 轮，0.25W，35nm，adaptive 1.5→0.5，
  无回溯；原 GPU 后处理 24/8/8、cooperative，所有参数一致，仅 α 不同。
- 先预热，五组配置各运行三次，偶数轮反序；表中各时间列分别取中位数。
  不删除慢样本，不将几个不同列的中位数直接相加；时间差未做统计显著性判断。
- 命令时间包含建图、优化、CSV、独立末态检查，排除 `read_db` 和预热。
  `total_ms` 只包含优化，不含建图；迭代与后处理另列。
- 增加线长为 trim 模型的延长量，并非写回真实布线；每个测量样本检查实际普通
  `dbWire` 原长保持 89,786.472µm。无 GUI 时完整坐标下载仍仅最终每层一次，共 2,661,312 bytes。
- ≥5nm 包含恰好 5nm；小违例严格为 `0 < 残差 < 5nm`。连续阶段仅用 `1e-6 DBU`
  过滤数值噪声；整数阶段精确判断正残差。

新参数取 `0.01` 时，已与修改前实际编译运行的 main CSV 逐层、逐轮、逐阶段对比：
能量、线长、残差数量、候选与跳跃数均一致，而非只核对最后一行。

## 实现、验证与复现

原有边势能、度数归一化、候选次数、移动域、跳跃、学习率反馈和后处理代码均未增加步骤。
GPU 只多传递一个常驻标量，不增加设备缓冲、kernel、同步或坐标下载。
CPU 参考保留原目标；显式给 CPU 传此 GPU 参数时报错。
CSV 增加 `wire_weight` 列，日志记录实际权重。C++、Tcl、启动脚本均保留基线默认值。

```bash
./dev-openroad.sh build-delgpu
# 新权重；省略 --wire-weight 则仍为 main 基线
./dev-openroad.sh optimize --gui 0 --wire-weight 0.05 --report /tmp/weight005.csv
# 同一算法在 GUI 展示
./dev-openroad.sh optimize --gui 1 --wire-weight 0.05

# 复现五组、三次交替测量
./dev-openroad.sh run -no_splash -exit \
  tools/OpenROAD/src/delgpu/scripts/benchmark_wire_weight.tcl \
  > /tmp/benchmark-wire-weight.log 2>&1
# 将上面的日志保存为实验目录中的 benchmark.log 后汇总
python3 tools/OpenROAD/src/delgpu/scripts/summarize_wire_weight.py
```

也可用 `DELGPU_BENCHMARK_DIR` 指定目录，`DELGPU_WIRE_WEIGHTS` 指定 Tcl 权重列表，
`DELGPU_SAMPLES` 指定重复次数。推荐连同日志一起指定目录：

```bash
mkdir -p /tmp/delgpu-wire-weight
DELGPU_BENCHMARK_DIR=/tmp/delgpu-wire-weight \
  ./dev-openroad.sh run -no_splash -exit \
  tools/OpenROAD/src/delgpu/scripts/benchmark_wire_weight.tcl \
  > /tmp/delgpu-wire-weight/benchmark.log 2>&1
python3 tools/OpenROAD/src/delgpu/scripts/summarize_wire_weight.py /tmp/delgpu-wire-weight
```

验证通过：78 项现有及新增 GPU/几何/优化测试；新增测试解析核对线长权重对能量和回拉
位移的影响，以及非正/非有限参数拒绝；Tcl 参数检查；无 CUDA 模块构建及 CPU 一轮运行；
以 α=0.05 运行 offscreen GUI，验证中间/末态更新与关闭覆盖层。性能表全部使用 GUI 关闭运行。
已恢复 CUDA 模块构建，GUI 宿主保留。

原始数据在 `flow/reports/asap7/ibex/base/delgpu_wire_weight/`，包含 15 份重复样本、
17 份探索样本、修改前 main CSV、日志、summary.json/csv/md、输入与源码哈希及回归记录。
