# 论文流程基准：剪枝与去除额外策略

日期：2026-10-15。对照本目录
[LEO 论文](<Pandey 等 - 2022 - LEO Line End Optimizer for Sub-7nm Technology Nodes.pdf>)
§4.1、§4.2；保留现有 A/B/C 工艺模型和数据库输入。
本次修改的是 `tools/OpenROAD/src/leo`，用户提供的 `module/leo-full` 未改动。

## 已实现的四项变更

| 用户要求 | 当前实现 |
|---|---|
| `P=k*Dt` 剪枝 | 默认 k=3，可用 `leo -prune_factor k` 指定。正权重保留 `[L,min(U,L+P)]`，负权重保留 `[max(L,U-P),U]`；随后删除必然合法的弧并划分子图 |
| 删除 16 遍坐标修复及回退 | `applyRanges` 整段删除。最终从全部已接受约束重新求解，直接使用最小可行坐标向量；没有从 ideal 开始修复，也没有修复失败时的替代坐标分支 |
| 删除 EMA 全 pivot 双向最大收益 | 固定 ID 顺序逐个尝试，只取该 pivot 减少自身延长量的方向；第一个负代价树移动立即提交并重新扫描，不排名全局候选 |
| 不使用增量传播和缓存复用 | 每个区间试探都从域端点初始化，对全部已接受约束和新候选进行完整 Bellman–Ford 扫描；上下界、队列、回滚、EMA 邻接/闭包/slack 都没有跨试探缓存；每个子图每个阶段独立创建数据 |

障碍域先在 OpenDB 坐标范围内完整求得，再做 ideal 端剪枝，不在求域前使用旧 20W 上限。
因此 k=5 可以保留 25W 的域。`buildArcs` 的搜索窗口根据剪枝后实际移动范围确定，
不会因旧 20W 窗口漏掉 k>4 的关联。
图构建沿用空间索引；这里移除的是求解器的增量状态和缓存复用，图本身和已接受的
约束仍是算法必需的数据。显示用图保存下来，不作为下一次求解的 warm start。

EMA 的 1000 次移动上限一并移除；每次移动严格降低有下界的整数目标，直到没有改进。
监测结构保留兼容字段 `limited=0`，当前求解不会返回 iteration_limit。

## 论文未明确规定的实现约定

论文说选择 pivot、建立零 slack 紧弧树、降低代价，但没有指定 pivot 的枚举顺序、
平局处理和确切方向选择。本版明确采用固定 ID、单个减少自身延长量的方向、首个改进。
它遵循上述已描述步骤，不能宣称与原作者未公开程序逐步相同。
LPA 的最终可行向量选取同样使用已公开的确定性约定：取 oracle 的最小可行向量。

初始排序保留现有弧凸包松弛的定义：可行时使用完整 oracle 的最小/最大坐标，
若该松弛模型本身不可行则采用域端点计算排序键。这个排序约定也未在论文中详细规定；
它不提供替代最终坐标，也不撤销已接受的区间。弧类型、slack 相同则按 ID 排序。

模型仍只有 A/B/C，`D=5W,Dt=5W,Du=3W`，权重为 ±1；尚未加入完整 EUV D/E、
rLEO 拆线重布、坐标写回和物理 DRC。因此应称为指定四项修正后的论文流程基准，
不能称为整篇论文全部功能或原作者二进制的严格复现。

完整 oracle 替换同时消除了旧增量实现的两个边界错误：ideal 起点可能误报不可行，
反向最大坐标传播可能遗漏前驱。新增反例和独立坐标穷举测试；没有把当前 ibex 结果
归因于旧错误，因为未证明其影响本数据的区间选择。

删除修复后，LPA 直接取最小可行坐标导致初始延长量增加，随后 EMA 将其压缩。
总违例仍为 340，说明此前低违例数并非主要来自 16 遍修复或全局最大收益移动。
主要消除违例的步骤仍是 LPA 显式选择联合可行的区间。≥5nm 数目的细微变化
来自最终未接受弧的残差变化，不代表所有违例进一步被消除。

实际 OpenDB regular wire length 始终为 **89786472 DBU**；上述延长量是图中模型量，
没有写回布线或执行物理 DRC。
