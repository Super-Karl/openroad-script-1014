# 全部违例统计与 LEO 论文复现审计

日期：2026-10-15。对照当前 `src/leo`、用户提供的 `module/leo-full`，以及本目录
[LEO 原论文](<Pandey 等 - 2022 - LEO Line End Optimizer for Sub-7nm Technology Nodes.pdf>)
第 4–6 页（§3、§4.1、§4.2、§4.3）。出版信息可查
[IBM Research](https://research.ibm.com/publications/leo-line-end-optimizer-for-sub-7nm-technology-nodes)。

结论：当前版本实现了 LEO 的 LPA+EMA 核心思路，含若干自行确定的实现策略，
缺少原论文的部分模型和流程，不能标注为原作者全流程的严格复现。
现有好成绩主要来自显式合法区间求解和 EMA 长度压缩，并非调用了隐藏的 MIP、
CPLEX、GPU 求解器或重布线后处理。

## 全部违例作为主指标

`leo` 现在默认输出所有正残差违例及 A/B/C 分类，可用 `leo -report result.csv` 保存。
判定为弧到全部合法区间的最小残差 **严格 >0**，无 5nm 门槛、无数值 epsilon。
双倍 DBU 坐标精确计算，0.5DBU 等小残差也会统计。
`remaining_5nm` 保留为辅助项；未选到可行区间的弧同样参与统计。

同一 ibex 输入的末态结果为：

| 层 | 全部违例 | A | B | C | ≥5nm |
|---|---:|---:|---:|---:|---:|
| M2 | 275 | 54 | 18 | 203 | 274 |
| M3 | 50 | 0 | 0 | 50 | 50 |
| M4 | 1 | 0 | 0 | 1 | 1 |
| M5 | 0 | 0 | 0 | 0 | 0 |
| M6 | 14 | 3 | 1 | 10 | 14 |
| M7 | 0 | 0 | 0 | 0 | 0 |
| 合计 | **340** | **57** | **19** | **264** | **339** |

仅一条 C 弧的正残差小于 5nm。已接受区间的违例为 0，未接受区间的弧为 340；
后者没有从最终评分中删除。统计仍然是图约束残差，未写回实际布线并运行物理 DRC。

本次只增加统计和复制图上的阶段审计；13 个 LPA、EMA、建图和主流程源码文件
与用户提供的 `module/leo-full` 逐字节相同。新增统计测试后共 42 项测试通过，
覆盖小于 5nm、等于 5nm、半 DBU、全部弧类型和未接受区间的计数。

## 为什么总违例明显少于当前 GPU

在复制图上从初始坐标重放原始 `solveLpa`、`solveEma`，没有改变原始运行结果：

| 阶段 | 全部违例 | ≥5nm | 模型延长量（µm） | 已接受区间违例 |
|---|---:|---:|---:|---:|
| 初始 | 104657 | 100303 | 0 | — |
| LPA 后 | **340** | 339 | 8676.686 | **0** |
| EMA 后 | **340** | 339 | **2441.901** | **0** |

因此，消除违例主要发生在 LPA；EMA 本次并未进一步减少违例数，而是将延长量
压缩了 **71.8568%**。EMA 会改变未接受弧的距离，例如最大残差从 48nm 变为 58nm，
所以“违例数没变”不表示每条未接受弧的残差不变。

LEO 逐弧选择可行区间，把它转成差分硬约束；保留的新区间必须与已经接受的区间
联合可行。EMA 在这些已选区间内部移动，始终维持其可行性。
这使大量约束的残差能精确等于零。无法在已选组合下接受的弧被标为 unresolved，
这是论文 §4.2.1 描述的启发式处理，不等于证明该弧在所有区间组合下都不可满足。

当前 GPU 是有限权重的软惩罚下降，并没有这一阶段的硬区间可行解构造。
其上一轮同环境实验统计为 77942 条（残差 >1e-6DBU），其中 ≥5nm 为 83，
其余 **77859 条**处在数值 epsilon 与 5nm 之间。
没有逐弧直方图时，不能把这 77859 条都称为浮点噪声。

即使梯度完全收敛，有限权重的惩罚模型也可能保留正残差。以 A 弧为例，
违规项近似为 `lambda * gap^2`：逼近合法边界时，纠错梯度趋近零，
却还要与非零的线长代价梯度平衡，因而平衡点可以落在略微违规的一侧。
所以“能量很低”和“全部残差为零”是不同目标。
LEO 的显式可行性约束与当前 GPU 的软惩罚目标不同，差距不能归因于 GPU 硬件。

运行时间也有工作量差异：LEO 的 85620 个弱连通分量中，有弧分量为 47280 个，
平均每个分量约 3.89 个节点。局部传播和整数移动成本低；GPU 则执行 200 轮，
反复扫描整层图、评估候选并读取摘要。上一轮 GPU 程序尚未接入等价 LPA+EMA 阶段。

## 哪些内容与论文一致

| 内容 | 对照结果 |
|---|---|
| 弧按类型、初始 slack 排序 | 符合 §4.2.1 的原则 |
| 优先尝试靠近 ideal 的合法区间 | 符合 §4.2.1 的原则 |
| 首个可行区间永久保留，失败尝试回滚 | 符合原则；没有撤销此前已接受弧的全局回溯 |
| 无可行区间则留下 unresolved 弧 | 论文明确允许，并交给后续 rLEO |
| 差分约束与最长路式可行性传播 | 对应论文的 LPA oracle 思路 |
| 沿紧约束移动节点组，只接受降低长度的移动 | 对应 §4.2.2 EMA 的核心思想 |

失败候选区间的事务回滚不是额外搜索所有旧区间组合，也不是 GPU 的步长减半回溯。
这几种“回溯”不能混为一谈。

## 没有严格对应或尚未实现的部分

1. **没有论文的剪枝流程。** §4.1 使用 `P=k*Dt`，论文实验评估并推荐 k=3。
   当前使用固定 20W 移动上限；Dt=5W 时 k=3 对应 15W，与 20W 并不等价。
   较大的可移动空间会改变可行域、图和启发式结果，不能与论文剪枝设置混用。
   当前 DEL/GPU 同样使用 20W，所以这不是它们之间差距的直接解释。
2. **只有简化的 A/B/C 模型。** D/Dt/Du 用 5W/5W/3W，未覆盖原文 D/E 类 EUV 约束、
   完整工艺规则及所有障碍物类型。因此不能称为完整工业 LEO 模型。
3. **LPA 取坐标增加了自己的修复策略。** `Lpa.cpp` 的 `applyRanges` 从 ideal 出发
   至多传播 16 遍，随后复核，失败时回到 `greedy.lower()` 的可行解。
   这不是原文完整规定的坐标恢复步骤，会影响 LPA 的初始延长量及后续 EMA 路径。
4. **EMA 的 pivot 调度是实现自行确定的。** 当前每轮枚举所有 pivot 的正负方向，
   选择总收益最大的可行移动，并规定平局顺序。原文只说明选择 pivot、构造紧弧树、
   沿最小 slack 移动，没有给出相同的全量最大收益选择或平局规则。
   当前使用有向紧闭包而非显式维护原作者的树结构，也没有逐步等价证明。
   这些细节可能改变结果，不能声称论文已经规定了本实现的每个选择。
5. **迭代上限是实现限制。** EMA 每子图最多 1000 次，原文没有给出同样的上限；
   本次 `limited=0`，上限未影响结果。停止于无单 pivot 改进也不应称为全局最优证明。
6. **没有 rLEO、坐标回写及最终几何复核。** 论文 §4.3 通过 rip-up/reroute 继续处理
   未解决子图；本实现保留了 340 条图违例，没有走这条流程。

逐层复用 scratch、只重置当前分量、增量队列传播和失败回滚属于工程加速，
并不是额外 MIP/ILP 优化器。全 pivot 最大收益和额外的坐标恢复属于算法实现选择。
阶段重放证明了 LPA 与 EMA 各自的贡献，但没有证明这些自选细节相对于原作者实现
一定改善了质量；没有原作者代码，不能作这种断言。

## 还发现两个辅助 oracle 问题

以下反例直接使用当前 `DifferenceConstraints.cpp`，未修改算法代码。
独立小程序仅用等价的三字段 `Constraint` 声明替代 Graph.h，以便隔离编译。

- **松弛排序模型从 ideal 起推可能误判。** 两节点域分别为 [0,10]、[0,0]，
  约束 `x1>=x0`。从 ideal=(10,0) 只允许抬高坐标，会返回不可行；
  从域下界 (0,0) 起推则可行，且 (0,0) 就是可行解。
  `Lpa.cpp:222` 当前对排序用松弛模型采用 ideal seed，可能触发不必要的排序回退。
  接受区间用的 greedy oracle 已从 low 起推，所以不能把此反例直接解释为其区间试加错误。
- **通用最大可行上界传播漏唤醒前驱。** 三节点域下界均为 0，上界 (100,100,0)，
  约束 `x0>=x1`、`x2>=x0`。真实最大可行坐标为 (0,0,0)，当前返回 (0,100,0)。
  当某节点上界变小，需要继续通知其前驱；当前代码只重新加入自身。
  本次松弛图主要由按 ID 向前的 A/B 弧构成，未证明该通用反例影响本次实测数值。

复现输出为：

```text
upper-propagation feasible=1 result=1 upper=0,100,0 expected=0,0,0
relaxation-seed ideal_feasible=0 domain_low_feasible=1 witness=0,0
```

这两处没有在本次暗中修复，以免改变 baseline。若修复，应作为单独版本重新测量。
它们进一步说明当前版本不能未经核验就标注“严格复现”。
