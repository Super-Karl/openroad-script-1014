# 延长量与残留违例的交换诊断

日期：2026-10-16。输入同此前 `asap7/ibex/base/5_2_route.odb`。
本轮仅增加独立诊断工具，没有修改 `leo` 求解器、默认参数或写回 ODB。
2026-10-15 基准的 43 个存档源码及构建/测试注册文件 SHA256 全部保持一致。

## 延长量为什么低

原 C++ 评估器计算：`sum(weight_i * (position_i-initial_i)) / (2*DBU)`，
高端权重 +1，低端权重 -1。双倍 DBU 整数精确评估；当前实际移动方向均为延长，
因此有符号延长量与位移绝对值总和一致。2441.818µm 是**图中的模型延长量**，
没有回写金属并计算几何并集增量，也没有执行物理 DRC。

当前代码调用的是 LPA、EMA，没有发现附加的隐藏线长求解器。EMA 本身就是论文
§4.2.2 的长度压缩步骤。真正的质量限制是：LPA 接受一个区间后不再重选，
未能接受的弧不进入 EMA 的可行约束，EMA 只压缩已选区间下的解。
未接受弧仍全部参与最终违例统计，未从评分中删除。

现有阶段记录尤其说明：LPA 延长量 22760.389µm 时已有 340 条违例；EMA 将其压到
2441.818µm 后仍是 340 条。因而增加长度本身不能改变已经锁定的区间组合。
目前仍为简化 A/B/C 规则，缺少论文完整工艺规则、rLEO 和物理复核，不能根据这个
延长量宣称超过原论文；原论文的 unsolved subgraph 数也不能直接与这里的违例弧数比较。

## 单弧可行性分类与剪枝实验

令弧两端的域为 `[Li,Ui]`、`[Lj,Uj]`，可达差值恰为 `[Lj-Ui,Uj-Li]`。
检查该区间是否与该弧任一合法区间相交。不相交则该弧单独也不可行，
与线长目标或其他弧的选择无关。分别检查剪枝域和未剪枝的金属障碍域。

k=3 时 340 条残留弧分为：

| 类型 | 完整障碍域内单弧也不可行 | 单弧可行、需检查联合约束 |
|---|---:|---:|
| A | 48 | 9 |
| B | 16 | 3 |
| C | 0 | 264 |
| 合计 | **64** | **276** |

没有一条属于“仅因 k=3 剪枝而单弧不可行”。单弧可行并不保证所有弧联合可行。
在当前固定金属障碍及 A/B/C 模型中，64 是违例数的一个下界。

| k | 弧数 | 全部违例 | ≥5nm | EMA 后延长量 µm |
|---|---:|---:|---:|---:|
| 3 | 372205 | 340 | 336 | 2441.818 |
| 4 | 437360 | 340 | 335 | 2441.843 |
| 6 | 546524 | 340 | 335 | 2441.886 |
| 8 | 634639 | 340 | 335 | 2441.964 |

放大 P 本次没有减少全部违例。应优先解决区间组合，而不是继续盲目增加移动上限。

## 独立联合区间求解

导出 k=3 下 249 个含残留弧的子图，共 5679 个节点、11600 条弧；最大子图 94 个节点、
211 条弧。使用独立 MILP 检查以下问题：

1. 节点保持在原剪枝后的金属移动域内，坐标仍为整数双倍 DBU。
2. 原本合法的弧必须在其**合法区间并集**内继续合法，但可以切换选中的区间。
3. 其余弧可选择任一合法区间或保留为违例。
4. 首先最小化违例数，再固定该数量最小化延长量。

采用每区间一个二进制变量、从节点域推导的有效 Big-M 上下界，调用
[SciPy milp 接口](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.milp.html)。
环境为 SciPy 1.15.3、NumPy 2.2.6，依赖只安装在 `/tmp/leo-mip-audit`。
249 个子图的数量阶段和长度阶段均返回 optimal。局部求解用时约 12.905 秒，
不包括 read_db、重建图、导出和 C++ 复核，不能与完整 `leo` 命令耗时直接对比。

将这些子图的候选坐标与其他子图的原坐标组合：

| 指标 | 原 LEO 基准 | 独立联合求解候选 |
|---|---:|---:|
| 全部正残差违例 | 340 | **76** |
| ≥5nm | 336 | **76** |
| A / B / C | 57 / 19 / 264 | **57 / 19 / 0** |
| 模型延长量 µm | 2441.818 | **2454.434** |
| 原本合法弧新增违例 | — | **0** |

只增加 **12.616µm，即原延长量的约 0.5167%**，消除 **264 条 C 弧违例**。
注意这是模型延长量的相对增量，不能称为实际整芯片线长增加 0.52%。

所有候选在 Python 中重新按整数坐标和完整合法区间并集评分；随后再次调用原 C++
`assessLayer` 逐层检查。还将每个节点的候选搜索域扩为初始位置 ±P 后重新建弧，
对更广的节点对复核，最终仍为 76 条，没有通过剪枝或漏统计隐藏新违例。

76 是“当前 k=3 子图、保护所有原合法弧”条件下的联合求解结果，不能无条件宣称
原始 LEO 问题的全局最优。剩余 76 条中 64 条单弧即受固定金属限制，另 12 条
在此次联合求解约束下仍不可消除。进一步突破 64 的下界需要改变固定几何或模型；
论文的 rLEO 正是通过邻近形状拆线重布来增加可行空间。

## 一个 3 节点实测例子

M2 子图 6837，节点 a=33674、b=33852、c=33931，以下为相对 a 原始位置的 nm 坐标：

| 节点 | 原 LEO 坐标 | 联合求解坐标 | 增加延长量 nm |
|---|---:|---:|---:|
| a（高端） | 0 | 8 | 8 |
| b（低端） | 62 | 8 | 54 |
| c（低端） | 98 | 98 | 0 |

约束是：B 弧 c-a 为 0 或至少 90nm；两条 C 弧 a-b、c-b 为 0 或绝对值至少 54nm。
原解 c-a=98 合法、a-b=-62 合法，但 c-b=36 违规。
联合解 c-a=90、a-b=0、c-b=90，全部合法，仅多出 62nm 延长。
它必须把已经接受的 C 弧从负分离区间切换到合并区间；在原选定区间内仅调整线长
权重或停止 EMA，无法得到这个解。

## 下一步实现建议

保持论文 baseline 不变，新增可选的局部区间重选阶段，只处理失败子图，目标按
“违例数量优先、延长量其次”排序。先允许切换少量邻近 C 弧的区间，用可行性求解
重算坐标，优先接受减少违例且不新增原合法弧违例的候选，随后再做 EMA。
GPU 可按子图并行尝试有限候选；实际加速和启发式质量需要再测，不能用此 MILP
诊断的结果保证 GPU 一定达到同样最优。

可先给全局模型延长量 +1% 的预算；已找到的候选实际只需 +0.5167%。
不要对子图用其原延长量的百分比作为唯一预算，原延长量为零的失败子图也可能需要
正的额外长度，以上 3 节点例子即如此。
