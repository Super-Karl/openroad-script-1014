# DEL 按关联弧阻力分配跨势垒位移

日期：2026-09-28。

状态：已实现并完成单元、Tcl 集成及同输入 Ibex 200 轮对照；功能正确，但本次加权版的 ≥5 nm 残留违例多于均分版。

## 1. 结论与范围

建议把跨势垒时的“双端优先均分”改为“双端按关联弧阻力的倒数分配”，同时保留移动域约束。阻力先采用 `r_i = 1 + k_i`，其中 `k_i` 为 trim 对应节点的关联弧总数，直接复用当前 `degree_[i]`。

这样，关联弧较多的一端优先少移动，关联弧较少的一端优先多移动。两端共同实现相同的目标中心差；如果一端移动域不足，另一端补足；联合移动域不足时整对不动。

本方案只调整跨势垒位移分配。保持普通梯度公式、停滞触发条件、5 nm 验收口径、目标势垒与跨越偏移量、弧处理顺序和 ODB 只读行为。它不是强制 merge，也不等同于精确合法化。

## 2. 当前每个 trim 的位移如何计算

代码依据：

- [Optimizer.cpp](../src/optimize/Optimizer.cpp)：`evaluate()`、`gradientStep()`、`step()`。
- [StallRepair.cpp](../src/optimize/StallRepair.cpp)：`jumpAcrossBarrier()`、`repairStalled()`。
- [Optimizer.h](../include/del/Optimizer.h)：状态与参数定义。

### 2.1 坐标与一轮更新的两个阶段

每个 trim 沿所在层的优选方向做一维移动。设层宽为 `W`（DBU），`z_i` 是求解器保存的归一化累计位移，则：

```text
连续物理位置 X_i = 初始位置 X_i^0 + W × z_i
累计位移（DBU） = W × z_i
本轮净位移（DBU） = W × (z_i^轮末 - z_i^轮初)
```

一轮先执行普通梯度更新，再尝试停滞弧的跨势垒跳转。第二阶段可能改变第一阶段的结果，因此整轮净位移不等于单次跳距。

GUI 用 `llround(W × z_i)` 绘制整数 DBU 位移。停滞判断也比较前后两轮这个取整值，而梯度、残差和跳转分配保留连续精度。当前 Ibex 数据中 1 DBU = 1 nm，但计算不能对其他数据库作同样假设。

### 2.2 普通梯度更新：已经考虑关联弧数量

当前目标为：

```text
E(z) = α Σ_i [sqrt(z_i² + ε²) - ε] + λ Σ_e φ_e(d_e)
α = 0.01，ε = 0.01
对于弧 e=(src,dst)，d_e = d_e^初始 + z_dst - z_src
```

每个端点梯度由自身的位移代价和所有关联弧贡献组成：

```text
g_i = α z_i / sqrt(z_i² + ε²)
      + λ × [以 i 为 dst 的 φ'_e 之和 - 以 i 为 src 的 φ'_e 之和]
```

代码中 `degree_[i]` 从 1 开始计数，所以它实际是 `1 + k_i`，不是裸弧数。先计算预条件方向：

```text
q_i = clamp(-g_i / (1 + k_i), low_i - z_i, up_i - z_i)
M = 本层所有节点的 max(|q_i|)
s = M > max_step ? max_step / M : 1
```

随后使用 `s × 2^(-backtrack)` 尝试更新，再做单步限幅与移动域投影；只有总目标足够下降才接受。普通方向失败后，还会尝试确定性的小扰动，仍要求目标下降。`-max_step` 是以 W 为单位的最大单步幅度，不是每个 trim 都固定移动该距离。

因此普通更新本身已经有“相同合力下，关联弧越多，位移越小”的机制。但不能说度数高就一定移动少：它也可能收到更多、更大的梯度贡献；不同弧的梯度还可能相互抵消。层内统一缩放、回溯和移动域同样影响最终位移。

### 2.3 修改前的跨势垒跳转：优先均分

当前对连续 3 轮两端整数 DBU 位置未变、且仍有 ≥5 nm 残差的弧尝试跳转。

设当前中心差为 `d`，势垒中点为 `m`，配置的跨越偏移为 `h`：

```text
d < m：目标 d* = m + h
d > m：目标 d* = m - h
```

恰在中点时，当前实现优先正侧；无法到达时再试负侧。B 的有限势垒中点为 `Dt/2`，C 为当前区间的 `-Du/2` 或 `Du/2`。A 类和 B 的负距离单侧惩罚没有有限势垒中点，继续普通优化。

这里的中点属于“两个端点的中心差”这个变量，不是版图上两点连线的几何中点。`h` 也不是每个 trim 分别移动的距离。

所需中心差变化是 `Δ = d* - d`。修改前优先把 `|Δ|` 各分一半，只有移动域不足时才重新分配；没有读取端点度数。普通梯度阶段的度数预条件当时没有延续到强制跳转阶段。现在已按第 4 节的公式分配。

## 3. 推荐的阻力模型

第一版使用：

```text
k_src = incident_arcs_[src].size()
k_dst = incident_arcs_[dst].size()
r_src = 1 + k_src = degree_[src]
r_dst = 1 + k_dst = degree_[dst]
```

包含所有关联 A/B/C 弧，也包含正在处理的弧和当前合法的弧。理由是：移动端点也可能破坏当前合法的约束，不能只看现有违例数。加 1 可保持正权重，并与普通梯度阶段一致。

这里的“阻力”是算法中的位移代价权重，是对周围约束影响的近似，并非物理阻力或精确刚度。仅凭弧数无法判断每条弧的活跃程度、距离合法边界的余量以及移动方向是否有利。

暂不直接以净梯度绝对值作为阻力：势垒顶部导数可能为零，多条弧的导数也可能抵消，这会把实际约束很多的端点误判为容易移动。

## 4. 双端加权分配公式

### 4.1 不考虑移动域时

以下推导中，位置、距离和移动域统一使用 DBU；实际实现可全部使用现有的 W 归一化单位，分配比例不变。必须先将配置的 nm 偏移换算到所选单位。

希望两端满足：

```text
δ_dst - δ_src = Δ
```

同时最小化加权位移代价：

```text
min  1/2 × r_src × δ_src² + 1/2 × r_dst × δ_dst²
```

其解为：

```text
δ_src = -Δ × r_dst / (r_src + r_dst)
δ_dst =  Δ × r_src / (r_src + r_dst)
```

注意，src 的位移份额使用分子 `r_dst`。这是按自身阻力的倒数分配，不是阻力越大分得越多。

- 两端阻力相同：退化为原来的各一半。
- src 阻力较大：src 少动，dst 多动。
- 两端移动方向相反，始终保持所需的中心差变化。
- 不额外放大总变化，不改变跨势垒目标。

这可以理解为把当前普通梯度的对角预条件思想用于跨势垒分配；不宣称它等于对真实周围规则势能的精确最小化。

### 4.2 加入移动域：对位移份额做一次投影

令：

```text
σ = sign(Δ)
T = |Δ|
a = src 承担的非负位移量
b = dst 承担的非负位移量 = T - a
δ_src = -σa
δ_dst =  σb
```

先根据实际移动方向计算两端的可用距离 `C_src`、`C_dst`：

| 中心差变化 | src 可用距离 | dst 可用距离 |
| --- | --- | --- |
| `Δ > 0` | `X_src - L_src` | `U_dst - X_dst` |
| `Δ < 0` | `U_src - X_src` | `X_dst - L_dst` |

其中 `[L_i,U_i]` 为该端点移动域。固定或 blocked 端的可用距离为 0。

可行份额区间：

```text
a_min = max(0, T - C_dst)
a_max = min(T, C_src)
```

若 `a_min > a_max`（排除现有 ULP 舍入误差处理），联合移动域无法达到目标，本次整对不动。

否则：

```text
a_preferred = T × r_dst / (r_src + r_dst)
a = clamp(a_preferred, a_min, a_max)
b = T - a
```

这是上述二次位移代价在当前约束下的最优份额，不需要另加迭代求解器。它也避免“分别给两端加权，再各自 clamp”造成中心差变化不够、未跨过势垒的问题。

计算两端新位置后，沿用现有检查：有限值、各自移动域、实际中心差接近 `d*`、位于势垒另一侧。整对检查通过后原子提交。边界舍入只接受现有量级的浮点误差，不能把真实不可达情况当作成功。

### 4.3 示例

假设需要让中心差增加 12 nm：

```text
src 关联弧 9 条：r_src = 10
dst 关联弧 1 条：r_dst = 2
```

| 策略/限制 | src 位移 | dst 位移 | 中心差增加 |
| --- | ---: | ---: | ---: |
| 原均分 | -6 nm | +6 nm | 12 nm |
| 按阻力分配，域充足 | -2 nm | +10 nm | 12 nm |
| dst 最多移动 7 nm，src 可补足 | -5 nm | +7 nm | 12 nm |
| src 最多 4 nm，dst 最多 7 nm | 不移动 | 不移动 | 无法达到目标 |

边界约束优先于“高连接端点少动”的偏好。高阻力端点并不是被固定，只是在可行分配中尽量少动。

## 5. 已实现的改动与范围控制

1. 在 `jumpAcrossBarrier()` 中复用 `degree_[arc.src]`、`degree_[arc.dst]`，不要另建一套含义不同的度数。
2. 将当前 `total * 0.5` 改为 `total * r_dst / (r_src + r_dst)`；权重先转为 double，避免整数运算。
3. 保留 `min_src`、`max_src`、联合可达检查、ULP 容差和原子提交。若舍入使两端边界轻微交错，仍按现有边界分支处理，不能对无效区间调用 clamp。
4. 分别清零两个实际发生移动端点的全部关联弧停滞计数，保持同一轮不重复跳转同一端点的行为。
5. 保留 ≥5 nm 筛选、连续 3 轮整数 DBU 停滞判断，以及 `n`、`c`、自动运行共用状态。
6. 保留现有三个全局配置项；第一版不新增可调指数。实验可用独立版本对照均分与加权，避免同时调多个参数。

核心变更可概括为：

```cpp
const double r_src = degree_[arc.src];
const double r_dst = degree_[arc.dst];
const double preferred = total * (r_dst / (r_src + r_dst));
const double src_share = min_src > max_src
                             ? max_src  // 仅在现有 ULP 容差分支内
                             : std::clamp(preferred, min_src, max_src);
const double dst_share = total - src_share;
```

额外的份额计算每次尝试为 O(1)。邻接计数已有缓存，无需重新扫描整张图。普通梯度更新不需要再除一次度数，否则会重复抑制高连接端点。

## 6. 日志与诊断建议

保留现有 `stall_triggered`、`stall_jumped`、`stall_unresolved` 和 `max_repair_um` 的含义：成功数按弧计，最大跳距按单端计。

为验证分配是否合理，建议后续增加可选逐次跳转 CSV，避免把大量明细写入控制台：

| 字段 | 用途 |
| --- | --- |
| iteration、layer、arc_id、type、src、dst | 定位本次跨势垒事件 |
| src_degree、dst_degree、src_resistance、dst_resistance | 解释阻力差异；区分裸弧数与加 1 后权重 |
| distance_before_nm、barrier_midpoint_nm、target_distance_nm | 确认目标未改变 |
| src_capacity_nm、dst_capacity_nm | 判断是否受域限制 |
| src_preferred_share_nm、src_actual_delta_nm、dst_actual_delta_nm | 对照理论份额和最终有符号位移 |
| domain_limited、result | 区分正常分配、域限制重新分配、不可达 |

为评估高连接端点是否更稳定，可离线统计每次跳转前后两端关联弧并集的 ≥5 nm 冲突数，以及目标弧在后续 1/5/10 轮是否重新回到原势垒一侧。关联弧按弧 ID 去重，避免目标弧在两端各计一次。需要解释其他约束影响时，将目标弧单独列出。

上述邻域统计只用于诊断，第一版不作为跳转硬性接受条件。强制“所有邻居立即合法”会重新引入此前难以触发有效跳转的问题。

## 7. 验证计划与结果

### 7.1 单元与小规模回归

- 两端度数相等时，结果与原均分一致。
- 度数比 10:2 的无域限制案例得到 1:5 的位移份额；交换 src/dst 后结果对称。
- B、C 正负势垒、增加/减小中心差均满足正确符号与目标距离。
- 两端单独都无法完成，但联合可达时成功。
- 任一端受限时正确重新分配，固定端不动，联合不可达时两端均不动。
- 目标恰在联合域边界时验证 ULP 处理，没有真实越界；阻力差较大时仍检查实际目标距离。
- 两端都有可用距离时，优先分配为双端非零；移动域可能迫使其中一端为零，不人为突破约束。
- 1000/2000 DBU 每 μm 下的 nm 换算一致；停滞判断与 GUI 取整口径保持一致。
- 跳转后两个端点关联弧计数均正确重置。
- `n/n/c` 与自动运行在相同初始状态和参数下产生一致轨迹。

新增用例按仓库要求同步注册 CMake/Bazel，优先扩展现有 `OptimizerTest.cpp`，测试尽量构造真实邻接弧，而不是只覆盖一行分配公式。

### 7.2 Ibex 对照实验

均分版本与加权版本分别从同一 ODB 开始，固定实际全局配置、输入 SHA-256、源代码版本及 200 轮预算，不混入步长、偏移量或阈值的改变。

至少比较：

- 每轮及最终 `remaining_5nm`，并分 A/B/C、分层统计。
- 初始冲突解决量与新增冲突量，避免只看净减少数。
- 规则势能、最大残差、extent 和耗时。
- 跨势垒成功/失败数、每端跳距及分配受域限制的比例。
- 高连接端点的位移分布、跳转后邻域新增冲突和目标弧回退情况。

用户提供的 200 轮日志中，`remaining_5nm=1011`、`extent=2600.262013 μm` 可作为待核对的历史参考；缺少该次完整配置和输入/源码快照时，不把它视为严格可复现的基线，也不预先承诺加权后一定更好。

## 8. 预期收益与局限

预期收益是让跨势垒跳转与普通梯度的度数预条件方向一致，减少强制拖动高连接端点对周围约束的扰动。是否能减少剩余冲突、降低回退或减少线长代价，需要实测。

关联弧多不等于真实阻力一定大：许多弧可能远离违规边界。因此先验证简单度数权重；若明显过度保护高连接节点，再考虑按方向、合法余量或正的局部曲率近似构造动态权重。有限势垒的二阶导数可能为负，不能直接把原始曲率当作正阻力。

本方案改变的是“到同一个跨势垒目标时，两端各走多少”，不改变 merge/separate 分支选择，不保证跨越后的目标弧或全部邻居立刻合法，也不防止后续梯度把它拉回原侧。若实测回退仍严重，再单独设计分支保持或跳转冷却策略，避免与本次分配策略一起变更、难以归因。

## 9. 实施与实测结果（2026-09-28）

`StallRepair.cpp` 已将 `total * 0.5` 改为 `total × r_dst / (r_src + r_dst)`，继续使用原有的联合可达区间、ULP 容差、实际目标校验与双端原子提交。未改变普通梯度更新、跨越目标、停滞条件或全局参数。`OptimizerTest.cpp` 新增真实邻接弧造成 6:2 / 2:6 阻力的双向用例，以及高阻力端点受移动域限制时由另一端补足的用例。19 项优化器测试全部通过；`del.optimizer_run.tcl` 也通过，包含 `n/n/c` 与自动运行的轨迹比对。

同一 ASAP7 Ibex `5_2_route.odb`、同一代码基线、`max_iterations=200`、`max_step=0.2W`、`jump_offset_nm=5`、4 线程，对原均分和新加权各运行一次。原均分版本取本次修改前的 `HEAD` 中 `StallRepair.cpp`，完成后已恢复加权源码并重建 `libdel.so`。输入 SHA-256：`3cd850a689bd2090e02496eccf724c1c31f60cb543450ec9cbf80370954599bd`。两次初始精确违例均为 98,402、≥5 nm 违例均为 94,411。

| 200 轮指标 | 原均分 | 按关联弧数加权 | 加权相对变化 |
| --- | ---: | ---: | ---: |
| ≥5 nm 残留违例 | 453 | 502 | +49 |
| 精确正残差弧数 | 77,197 | 78,305 | +1,108 |
| A/B/C 的 ≥5 nm 残留 | 14 / 311 / 128 | 14 / 300 / 188 | 0 / -11 / +60 |
| 规则势能 | 382.963550 | 368.116000 | -14.847550 |
| 累计端点绝对位移 `extent` | 2640.470268 μm | 2646.478027 μm | +6.007760 μm |
| 累计成功跳变弧事件 | 33,353 | 33,860 | +507 |
| 优化耗时（不含建图） | 48.419 s | 48.970 s | +0.551 s |

各层 ≥5 nm 残留：M2 为 358→401，M3 为 78→85，M4 为 8→7，M5 为 3→0，M6 为 5→8，M7 均为 1。由此可见，按关联弧数分配已实现并在小图上按预期工作，但**该次 Ibex 对照没有改善主要验收指标**；规则势能下降不能代替 ≥5 nm 残留数量的改善。`extent` 是覆盖层端点绝对位移和，不是已经写回 ODB 的实际线长。单次确定性对照也不足以推断其他设计的效果。后续若以残留违例为优化目标，应分析 M2/M3 中高关联度端点被保护后、低关联度邻端新增的 C 类残差；这属于下一轮策略设计，不能将本次结果直接宣称为 QoR 改进。
